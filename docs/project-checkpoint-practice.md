# Project checkpoint practice

Maintain the root `PROJECT_CHECKPOINT.md` as the concise restart anchor for this
repository. Update it at the end of every meaningful analysis or simulation
milestone and before pausing, changing campaign, or handing work back to the
user.

Each checkpoint should record:

1. date, branch, current repository commit, and worktree state;
2. objective and status, including completed/expected task counts;
3. conclusions and their scope limits (especially sampled versus global claims);
4. canonical manifests, code, reports, local result paths, and checksums;
5. Google Drive folder/file IDs and verified links for uploaded artifacts;
6. the next concrete action and unresolved choices or risks.

Do not treat a chat transcript as the durable project record. The checkpoint
summarizes decisions and points to immutable source artifacts; preserve raw
simulation data in the established Drive hierarchy rather than committing
generated run directories to Git. Verify Drive uploads by listing the target
folder. Keep the checkpoint brief enough to read first when resuming.
